# 项目决策记录

本文件记录影响长期开发、架构和发布流程的正式决定。新决策使用连续 `DEC-NNN` 编号；被替代或撤销时保留原记录并标明关联决策。

## DEC-001：稳定版本与研发版本序列

- 决策标题：保持 `v1.0.40` 稳定基线，下一轮从 `v1.0.42` 开始
- 状态：被替代
- 背景：`v1.0.41` 本轮界面研发未达到要求，需要重新开发且不复用版本号。
- 最终决定：远端和稳定基线保持 `v1.0.40`；`v1.0.41` 版本号作废；下一轮本地开发版本为 `v1.0.42`。
- 选择理由：避免把失败研发与重新实现混为同一版本，保持版本历史清晰。
- 已知风险：稳定版与本地研发版不同，文档和脚本必须明确区分。
- 影响模块：版本管理、部署脚本、交接文档、测试。
- 替代方案：复用 `v1.0.41`；已拒绝，因为会混淆两轮实现。
- 关联想法、任务和版本：`v1.0.40`、`v1.0.41`、`v1.0.42`、`DEC-007`。

## DEC-002：本地优先与远端推送授权

- 决策标题：默认仅在本地开发，推送必须获得明确许可
- 状态：生效
- 背景：长期项目需要先本地验收，避免未经项目所有者确认改变远端稳定版本。
- 最终决定：允许本地分支和本地里程碑提交；禁止未经项目所有者明确同意执行推送、远端分支、标签、发布或远端合并。
- 选择理由：同时获得可靠恢复点和远端发布控制权。
- 已知风险：本地提交只存在当前电脑，需要项目所有者批准后才具备远端备份。
- 影响模块：全部开发、Git 工作流、发布流程。
- 替代方案：不创建任何提交；已拒绝，因为 AI 中断时恢复能力较弱。
- 关联想法、任务和版本：`local/v1.0.42`，AI 续接体系。

## DEC-003：当前状态与历史记录分离

- 决策标题：使用单一当前状态入口和追加式历史日志
- 状态：生效
- 背景：原交接文档混合当前状态、历史需求、故障和架构，下一位 AI 难以快速定位。
- 最终决定：`docs/current-status.md` 是唯一当前状态入口；`docs/work-log.md` 追加检查点；`docs/conversation-handoff.md` 仅保留历史背景和业务经验。
- 选择理由：让无聊天上下文的 AI 快速恢复，同时保留完整历史。
- 已知风险：关键动作后若不更新状态会产生偏差，因此由 `AGENTS.md` 和自动检查约束。
- 影响模块：文档、AI 工作流程、验收流程。
- 替代方案：继续维护单一超长交接文档；已拒绝，因为当前与历史容易冲突。
- 关联想法、任务和版本：AI 续接体系、`v1.0.42`。

## DEC-004：架构权威来源

- 决策标题：以 `docs/project-architecture.md` 作为当前架构权威说明
- 状态：生效
- 背景：架构信息曾散落在 README、交接文档和追加章节中。
- 最终决定：当前架构、API、运行时通信和数据保护统一维护在 `docs/project-architecture.md`；历史讨论不写入架构正文。
- 选择理由：减少多个架构事实来源。
- 已知风险：架构修改时必须同步更新该文档。
- 影响模块：架构文档、开发交接、代码审查。
- 替代方案：以聊天或历史交接为准；已拒绝，因为不可验证且容易过期。
- 关联想法、任务和版本：AI 续接体系、`v1.0.40` 架构基线。

## DEC-005：关键动作立即记录检查点

- 决策标题：关键动作后更新状态，不等待对话结束
- 状态：生效
- 背景：AI、客户端或网络可能在任意时刻中断。
- 最终决定：需求确认、决策、修改、测试、阻塞和暂停后立即更新当前状态，并向工作日志追加记录。
- 选择理由：将单次中断可丢失的信息压缩到一个关键动作以内。
- 已知风险：文档更新频率增加，需要保持记录简短。
- 影响模块：全部开发任务和交接文档。
- 替代方案：只在每轮结束或里程碑更新；已拒绝，因为中途宕机会丢失上下文。
- 关联想法、任务和版本：AI 续接体系。

## DEC-006：需求驱动拆分与技术债自动守卫

- 决策标题：不全面重构，通过小范围拆分和自动预算持续改善
- 状态：生效
- 背景：`src/index.js`、`public/app.js`、`src/dashboard.js` 和双层 CSS 已达到较高维护复杂度，但一次性重构风险过大。
- 最终决定：只在真实 bug 或功能改动触及明确边界时提取独立模块；维护校验约束 Dashboard API 测试引用、CSS 重复选择器、`!important` 数量和大型文件行数预算。
- 选择理由：让每次迭代产生可验证的小改善，同时防止技术债继续无声增长。
- 已知风险：现有 80 个重复 CSS 选择器和 12 个 `!important` 仍存在，需要随具体界面需求逐步减少。
- 影响模块：Dashboard、Mineflayer、前端、CSS、测试和 AI 开发流程。
- 替代方案：一次性拆分全部大型文件并合并样式；已拒绝，因为回归面过大且缺少当前业务目标。
- 关联想法、任务和版本：`IDEA-001`、`IDEA-002`、`src/json-store.js`、`scripts/maintenance-check.js`、`v1.0.42`。

## DEC-007：发布 v1.0.42 并重新关闭远端权限

- 决策标题：将 `v1.0.42` 发布为当前稳定版，下一开发版本暂不启动
- 状态：生效
- 背景：项目所有者审阅后明确要求“推送”，本地发布源 `local/v1.0.42` 已通过交接、维护、安全和完整业务测试。
- 最终决定：将本地提交 `8f37dde` 快进推送到远端 `main`；当前稳定版和已完成本地开发版均为 `v1.0.42`。不创建标签或额外远端分支，不预先启动下一开发版本。本次许可在发布完成后失效，后续远端变更重新要求明确许可。
- 选择理由：让已审阅成果成为远端稳定基线，同时保持版本启动与发布权限由项目所有者控制。
- 已知风险：本地 `main` 可能暂时落后于远端跟踪引用，但发布源分支和远端 `main` 指向同一发布提交；新开发开始时需先明确版本号和本地分支。
- 影响模块：版本状态、远端基线、AI 续接、Git 工作流和发布流程。
- 替代方案：发布后自动创建 `v1.0.43` 分支；已拒绝，因为项目当前处于停止状态且未获得新一轮开发授权。
- 关联想法、任务和版本：`DEC-001`、`DEC-002`、`v1.0.42`、`local/v1.0.42`、`8f37dde`。

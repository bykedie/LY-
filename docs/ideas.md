# 项目想法收件箱

本文件只记录尚需评估或需要保留理由的产品、技术和流程想法。新想法使用下一个连续 `IDEA-NNN` 编号；确认后关联任务或 `docs/decisions.md`，不删除历史。

## 状态定义

- `待评估`：尚未形成决定，不能作为既定需求实施。
- `已接受`：已转为明确任务或正式决策。
- `已拒绝`：不采用，并保留理由避免重复讨论。
- `延后`：当前不做，注明重新评估条件。

## IDEA-001：模块化拆分大型核心文件

- 提出时间：2026-07-23
- 来源/背景：`src/dashboard.js`、`src/index.js` 和 `public/app.js` 职责持续增长。
- 想法摘要：随具体功能逐步拆分配置、进程、协议和前端模块，避免一次性全面重构。
- 预期价值：降低改动影响范围，提高测试和 AI 续接效率。
- 不确定因素：模块边界应由后续实际需求验证，提前拆分可能制造额外复杂度。
- 影响范围：Dashboard、Mineflayer 执行端、前端交互、测试。
- 状态：已接受
- 关联任务或决策：采用需求驱动的小范围拆分；本轮已把原子 JSON 存储提取为 `src/json-store.js`，不得单独发起无业务目标的全面重构。

## IDEA-002：减少双层 CSS 覆盖

- 提出时间：2026-07-23
- 来源/背景：`public/styles.css` 与 `public/workbench.css` 存在覆盖关系，上一轮界面研发暴露维护风险。
- 想法摘要：在 `v1.0.42` 的明确界面需求中梳理样式职责，减少末尾叠加式覆盖。
- 预期价值：降低响应式冲突和视觉回归风险。
- 不确定因素：尚未确定下一轮界面目标，不能脱离需求重写样式。
- 影响范围：`public/index.html`、`public/styles.css`、`public/workbench.css`、`scripts/smoke-test.js`。
- 状态：已接受
- 关联任务或决策：先以维护校验锁定 80 个完全重复选择器和 12 个 `!important` 的现状基线；后续界面需求只能降低或保持，不得未经审阅增加。

## IDEA-003：版本号单一来源

- 提出时间：2026-07-23
- 来源/背景：版本号目前需要同步部署脚本、测试和文档。
- 想法摘要：未来评估由单一文件或脚本生成版本引用。
- 预期价值：减少版本漏改和部署版本不一致。
- 不确定因素：部署脚本需要可独立下载，单一来源不能破坏 bootstrap 的自包含能力。
- 影响范围：部署脚本、测试、文档、发布流程。
- 状态：延后
- 关联任务或决策：下次真实发生版本同步遗漏或发布流程改造时重新评估。
